GCS: QGroundControl 5.0.8, same-phone loopback on UDP `14550`

Observed on 2026-09-01 using the same implementation working tree before the version-only metadata bump and notification-API cleanup:

1. MAVLab started its foreground service and MAVLink endpoint normally.
2. Backgrounding without QGC displayed the handoff notification, then stopped the service and MAVLink cleanly after the 45-second window.
3. Switching to QGC produced sustained SYSID 255, COMPID 190, `MAV_TYPE_GCS` heartbeats on loopback.
4. MAVLab changed its notification to the connected-GCS state and remained active beyond the handoff deadline.
5. After QGC stopped, MAVLab stopped once heartbeat expiry and the remaining handoff grace had both elapsed.
6. No MAVLab `FATAL EXCEPTION` was observed during these lifecycle scenarios.

The final version bump and notification icon API cleanup did not change runtime policy, simulation, sensor, or MAVLink behavior. The final APK could not be reinstalled because the phone disconnected before release freeze.
