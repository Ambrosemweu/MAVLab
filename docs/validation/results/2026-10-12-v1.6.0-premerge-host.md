The certificates differ. The local candidate cannot seamlessly replace that official APK. Availability of the original private release keystore is unknown. Only repository secret names were listed; the existing opaque `MAVLAB` secret was not read, repurposed or assumed to contain a key. No real signing key was read/uploaded and no new Actions secret/variable was configured.

The tag workflow now requires approved stable APK signing inputs and verifies the configured certificate before final checksums/publication. Maintainer decision is required: recover/use the old release identity, or explicitly approve key/data migration with user backup instructions. This is a publication blocker, not evidence of an engine defect. It does not establish Play signing or solve a migration by uninstalling user data.
