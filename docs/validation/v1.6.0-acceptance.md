# v1.6.0 acceptance specification

Status: Specification, not a PASS record. Intended build: 1.6.0/code 19.

Use an isolated simulated vehicle/network without real aircraft or uncontrolled MAVLink endpoints. Identify APK checksum/commit, phone/Android, exact QGC build, connection mode, tester and date in a new result record. Save QGC plans and export valuable recordings first. Begin disarmed with recording stopped; do not clear app data. Obtain agreement before installing or controlling the user's phone. Use intentional horizontal swipes, not vertical scrolls, to test screen navigation.

Do not fly through arbitrary exclusion/nonconvex regions expecting route planning: endpoint eligibility is not obstacle/path safety. A report should identify unsupported/partial command semantics rather than mark them complete.

## Evidence and dispositions

Unit/isolated Android passes support only their tested logic. Live QGC nonempty transfers and recovery need actual named-build evidence; a heartbeat or video montage is insufficient. Record PASS, FAIL or NOT RUN per scenario with evidence. Existing earlier findings/results remain immutable; the new record may reference their closure and exact scope.

For broader qualification, separately exercise TalkBack (swipe disabled/buttons usable), multi-window, other Android versions/navigation modes, LAN telemetry arrival, frame timing under load and model-loader crash history. Scope any supported-device claims to the tested devices. See [readiness](../operations/v1.6.0-readiness.md) and [validation policy](README.md).
