# Full screen and compact navigation handoff

Editable source: [mavlab-onboarding.pen](../mavlab-onboarding.pen). Existing onboarding and all 72 original root nodes are unchanged. The Pen design skill guided reuse of existing approved screens and a single reusable dock component rather than replacing their visual language.

New component `Zpqzs`: **Shell Compact Navigation — 56 dp**. Four equal 90 × 56 design-unit hit regions at 360-wide default scale; 22-unit icons and 12-unit labels. These are logical design targets, not a claim about exported pixels or device insets.

New handoff board `z5f7s` contains eight reusable shell cases and interaction/safe-area annotations. All four selected-destination variants use references to the same dock.

The received-mission SIM fixture illustrates existing mission state, not a route generated by the application. System bars/keyboard are illustrative; Android must use measured insets. Active content reflows/scrolls in the implementation. These shell examples do not redesign every underlying screen.

Visual checks: dock screenshot and overview inspected; no enabled layout-clipping issues reported in the new board; no unfinished placeholders. Exported through Pen at 2×. Structural comparison found no changes to original root subtrees.

Follow-up user testing expanded swipe eligibility to Cockpit's passive instruments/non-mission status text and Control's phone-tilt preview. Those annotations are saved in the editable Pen board. The overview re-export hit external font-download timeouts and produced fallback glyphs; that invalid overview is retained only in validation diagnostics, not presented as a finished preview. The eight individual 2× PNGs and dock export retain the verified earlier visuals. Use the canonical guide and latest editable board for gesture eligibility.
